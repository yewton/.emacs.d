## 3. タイマーと失敗時の復元

- [x] 3.1 表示成功後・表示済み一覧の再選択・専用 `g` コマンドでタイマーを開始する。モード初期化と内部の再描画では開始しない。
- [x] 3.2 最小化中は可視性の確認だけを行い、復帰後に更新を再開する。`q` / トグルで最後の一覧ウィンドウを閉じた際に即時停止し、外部操作で全ウィンドウから消えた場合は次回タイマーで停止する。
- [x] 3.3 バッファ削除・モード変更・更新エラーでタイマーを停止する。削除 hook を通らない消失時の自己停止と、古いコールバックが再開後のタイマーへ影響しないことも検証する。内部の強制再描画で停止済みタイマーが再開しないことを検証する。
- [x] 3.4 表示処理のエラー・中断時に新規ウィンドウとタイマーを解放する。

- [x] 3.5 ウィンドウ設定の保存・復元と永続パラメータ登録を撤去する。Emacs 標準の window-side / window-slot 登録を許容し、独自パラメータの永続登録がないことを検証する。
- [x] 3.6 再描画が必要な場合だけ位置の取得・復元準備を行う。

- [x] 3.7 更新間隔を設定可能にする。既定1秒、0.2秒への切り替えとモード確認を先に行ってから副作用前に正の値を確認し、不正値でも閉じられることを検証する。

## 試用方法と検証範囲

Emacs を再起動して `M-x toncs-ghostel-sidebar` で開く。`n` / `p` と `RET` または左クリックで端末を選び、長いタイトルの折り返しと自動反映、`g` 更新、`q` 終了、トグルによる再表示を確認する。

高速に変化するタイトルを試す場合は `M-:` で `(setq toncs-ghostel-sidebar-refresh-interval 0.2)` を評価し、一覧で `g` を押す。既定へ戻す場合は値を `1.0` にして `g` を押す。再描画負荷と、項目内の位置が先頭へ戻る影響を実機で確認する。

ローカル検証は Emacs 31.1。`ERROR_ON_WARN=t make test` で独立起動2件と通常82件が成功し、tangle・警告をエラー扱いにしたバイトコンパイル・OpenSpec strict 検証・`git diff --check` が通過した。`ERROR_ON_WARN=t make test` は二つの独立起動テストと通常 ERT を別プロセスで実行する。ユーザーによる実機の基本動作確認も完了した。実機確認の個別条件は記録していない。Emacs 30 系はローカル未実行。

項目内のカーソル・スクロール位置保持と、表示先の MRU 選択は別途検討する。

## 更新負荷の参考値

Emacs 31.1 のバッチ環境で追加500バッファ・タイトルが変化する10端末を用意し、100回の更新を測定した平均は約0.19ms/回だった。GUI の再描画は含まないため、0.2秒更新での操作感は実機で確認する。
