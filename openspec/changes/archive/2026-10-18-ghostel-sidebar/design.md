## Context

`consult-ghostel` の注釈で使われる `ghostel-title` を、常設の一覧から確認したい。端末タイトルの表示は `lisp/toncs-ghostel-sidebar.org`、端末の登録順は `lisp/toncs-config-ghostel.org` に配置する。Org から tangle して生成ファイルを更新する。

## Goals / Non-Goals

**Goals:**
- 名前と全文タイトルを確認し、選択した端末へ移れる試用可能な一覧を提供する。
- 既存パネルを維持し、表示・終了・更新のライフサイクルを簡潔にする。
- 更新間隔を調整して、高速に変化するタイトルの表示を試せるようにする。

**Non-Goals:**
- エージェント固有の状態分類・通知、プロジェクト別絞り込み、端末作成。
- アニメーションの全フレーム同期、ウィンドウ構成の保存・復元への専用対応。
- 項目内のカーソル・スクロール位置の厳密な保持。

## Decisions

### 読み込みと登録順

`toncs-config-prepare ghostel` の BODY で公開コマンドの autoload を登録する。ghostel 設定は専用設定ファイルの configure 関数で行う。サイドバーでは ghostel を先に require し、その after-load 設定が完了してから設定ファイルを require することで、ロード途中の設定ファイルへの再入を防ぐ。

`toncs-ghostel-register-terminal` は、バッファが未登録の場合だけ `toncs-ghostel-terminal-order` の末尾へ追加する。モード切り替え後も登録順を保持し、ghostel-compile の再ビルドで末尾へ移動しないようにする。登録時にバッファローカルな kill-buffer-hook を設定し、削除時に登録記録から除去する。この hook はモード切り替え後も保持する。表示時にも死んだ記録を除去する。端末を開くだけではサイドバー UI をロードしない。

### 表示とウィンドウの所有

一覧は読み取り専用の special-mode 派生モードとし、名前と全文タイトルを折り返して表示する。タイトル未設定と空一覧を明示する。

サイドバーは右側の slot 1 を使用し、汎用パネルの slot 0 と分離する。slot 1 が使用済みの場合はエラーを通知する。右側に既存パネルがある場合は、新しい専用ウィンドウを明示的に分割する。右側にパネルがない場合は Emacs 標準のサイドウィンドウ作成を使う。slot 数の上限や画面サイズで作成できない場合はエラーを知らせ、既存パネルの表示を維持する。

所有する新規ウィンドウに `toncs-ghostel-sidebar` パラメータを付け、終了時はそのウィンドウを delete-window する。通常ウィンドウの一覧を閉じる場合は標準の quit-window を使う。既存パネルの設定を保存・復元する機構は持たない。

Emacs 標準の表示処理が行う window-side / window-slot の永続パラメータ登録を許容する。サイドバー独自のパラメータは永続登録しない。サイドバーを保存済みウィンドウ構成から復元する機能は提供しない。

表示途中のエラー・中断では、新しく作ったウィンドウとタイマーを削除する。正常に表示できた場合だけタイマーを開始する。通常ウィンドウに一覧が表示済みの場合は選択・更新してタイマーを再開し、追加の一覧を作らない。

### 更新と操作

移動量0ではカーソル位置を維持する。`n` / `p` で項目移動、`RET` / 左クリックで端末へ移動する。クリック先のウィンドウとモードを確認してから選択を移す。呼び出し元の通常ウィンドウを優先し、無効な場合は同じフレームの通常ウィンドウを使う。一覧を表示するウィンドウは端末の表示先から除外する。

タイマーはバッファごとに一つとし、表示成功後と専用の `g` コマンドで開始する。最小化中は可視性の確認だけを行い、全ウィンドウから消えた場合は次回タイマーで停止する。`q` / トグルで最後の表示を閉じた場合は即時停止する。バッファ削除・モード変更・更新エラーでも停止する。コールバックは自身のタイマーを保持し、削除 hook を通らず一覧バッファが消失した場合も次回実行で自己停止する。停止前の古いコールバックが呼ばれても、再開後のタイマーを停止しない。内部の再描画はタイマーを開始しない。

更新時は buffer-list から全 ghostel バッファを発見する。判定は provided-mode-derived-p と buffer-local-value で行い、カレントバッファを切り替えない。発見した未登録端末も共通の登録関数で登録順の末尾へ追加し、同じ削除 hook を設定する。登録記録を唯一の並び順とし、ハッシュ表は既知端末と表示対象の判定に使う。後から作られた端末は末尾に追加され、既存項目へ割り込まない。バッファ一覧は描画スナップショットから取得し、重複した状態を保持しない。各端末の名前とタイトルを取得し、スナップショットが変わった場合だけ位置情報を取得して再描画する。選択項目はバッファオブジェクトで復元する。項目内の位置保持は別途検討する。

### 更新間隔

`toncs-ghostel-sidebar-refresh-interval` の既定値は1秒とする。0.2秒に設定すると毎秒5回の取得を試せる。設定変更は `g` または開き直しで適用する。更新間隔は表示・再描画・タイマー変更の前に検証し、不正値の場合は既存状態を維持する。閉じる操作は不正値でも実行できる。取得時点の最新タイトルを表示するため、途中のアニメーションフレームは飛ぶ場合がある。

### 検証

make test で「サイドバーを先に開く」「端末を先に開く」の二つの起動経路を別プロセスで検証し、通常の ERT スイートを続けて実行する。初回起動テストは load-file-name を基準に補助ファイルを探す。設定のロード回数は load-history の provide 情報から数え、ファイル拡張子に依存しない。失敗時は make の通常の動作として後続処理を停止する。

## Risks / Trade-offs

- [更新頻度を上げると再描画負荷が増える] → 既定は1秒とし、実機で0.2秒を試して選択する。
- [サイドウィンドウを追加できない場合がある] → 既存パネルを維持して作成失敗を通知する。
- [更新時に項目内の位置が先頭へ戻る] → 試用時の既知の制約とし、位置保持は別途扱う。

## Deferred Decisions

- **slot 2以降のパネルとの画面上の並び**：専用slot 1と共通slot 0の衝突防止を優先する。slot 2以降のパネルも使う構成で、物理的な並びを常にslot順へ整える処理は試用後に判断する。
- **ウィンドウ構成の保存・復元**：専用パラメータを永続化すると、復元されたウィンドウの所有権・タイマー開始・終了方法まで整合させる必要がある。初期版はコマンドによる新規表示を提供し、復元された専用ウィンドウへの対応を別の変更として扱う。
- **共通サイドパネルの所有権管理**：現在は専用パラメータによってサイドバーを共通パネルの操作対象から除外する。共通パネル自体に所有マーカーを付ける設計は既存キーの動作にも影響するため、別の変更として扱う。右側のslot数を制限した構成では、共通パネルの新規表示がサイドバーを再利用する場合がある。
- **項目内のカーソル・スクロール位置保持**：選択項目の識別を維持しつつ、描画は変更時の全文更新とする。項目内のオフセット保持や部分描画は別途設計する。0.2秒更新では位置が先頭へ戻る影響も実機試用で確認する。
- **初回起動テストの追加プロセス**：サイドバー先行と端末先行をそれぞれ未ロード状態から確認するため、独立したEmacsプロセスを使う。単一プロセスへの統合にはfeatureやhookの巻き戻しが必要になり、初回起動の検証条件が不明瞭になるため独立性を維持する。

## Migration Plan

change/ghostel-sidebar ブランチで変更を検証する。再起動後に M-x toncs-ghostel-sidebar で試用する。実装と動作確認を完了した change はアーカイブし、成果物を含む PR を作成する。ロールバックは追加設定を戻して再ビルドし、一覧バッファを削除する。
